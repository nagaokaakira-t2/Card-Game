# カードゲーム(仮)

ブラウザで遊べる 1vs1 対戦カードゲーム。`index.html` を開くと
「対戦相手選択 → デッキ/能力の編集 → 対戦」の順に進みます。

## 今回の主な改善点

- **カード効果が実際に発動するようになりました**(以前はテキスト表示のみ)。
  召喚時/使用時/攻撃時/ターン開始・終了時/破壊時など、カードごとの効果が
  自動で実行されます。
- **カードの使用フローを「選択 → 内容確認 → 実行」に変更**。手札のカードや
  自分のクリーチャーをタップすると、詳細と実行ボタンが専用エリアに表示され、
  誤操作なく内容を確認してから使えます。
- **行動ログを「〇〇の攻撃/効果/召喚/使用: 内容」という形式に統一**し、
  画面上部にも直近の行動をバナー表示するようにしました。
- **簡易盤面パネル**を新設。HPバー・光・山札枚数・場のクリーチャー数・
  手札枚数を、詳細なカード表示とは別に一目で確認できます。
- **デッキ構築画面を属性ごとの列に分割**、さらに各列の中でクリーチャー/
  特殊効果も分けて表示するようにしました。

## 画面の流れ

1. **対戦相手選択**: CPU対戦(かんたん) / AI対戦(強め) を選ぶ
2. **デッキ/能力編集**: 自分のデッキ(50枚)とプレイヤー能力(コスト合計13まで)を編集する
   - 属性(火・水・風・土・天・冥)ごとに列が分かれ、各列内でクリーチャー/特殊効果も分離
   - 「AIにおまかせで残りを埋める」: 今選んでいる分は残したまま、足りない分だけランダムに埋める
   - 「デフォルトデッキ/構成(全ランダム)」: 選択中の内容をリセットして全てランダムに組み直す
   - 「おまかせでそのまま開始」(画面右上): 編集を一切せず、フルランダムで即対戦開始
   - デッキがちょうど50枚になると「この内容で対戦開始」が押せるようになる
3. **対戦画面**: 実際のバトル。簡易盤面 → 相手の場 → 自分の場 → 選択中カードの詳細/実行確認
   → 手札 → プレイヤー能力 → ログ、の順で並んでいます

対戦相手(CPU/AI)のデッキと能力は、いつも自動でランダム構築されます。

## 属性

各属性には明確な設計思想(デザインピラー)を与え、効果プールとステータス傾向を
分離しています。以前は4属性(火水風土)が同じ効果プールを共有していて
「名前が違うだけの同じカード」になっていましたが、今は属性ごとに専用の
効果プールとステータス配分を持ちます。

| 属性 | コンセプト | ステータス傾向 | 効果の中心 |
|---|---|---|---|
| 火 | 焼き尽くす速攻 | 高攻撃・低HP | 相手クリーチャーへの直接ダメージ、攻撃時の追加ダメージ |
| 風 | 疾風の連撃 | やや攻撃寄り、バランス型 | ターン経過で育つ攻撃力、ドロー、一部に【速攻】(召喚酔いなし) |
| 水 | 癒しと粘り | 高HP・低攻撃 | HP回復(自分/味方クリーチャー)、相手の弱体化 |
| 土 | 不動の要塞 | 最高クラスのHP | 光の安定供給(パッシブ)、破壊時の回復 |
| 天 | 捧げて加速する | 攻守バランス型 | 光・ドローの加速と引き換えに自傷ダメージ |
| 冥 | 喰らい、削る代償の力 | 攻守バランス型 | 除去・妨害と引き換えに自傷ダメージ |

- **4属性すくみ**: 火・水・風・土。隣接属性に強く逆隣に弱い循環関係で、
  有利/不利は**ダメージ2倍/0.5倍**。
- **天・冥**: 4属性とは無関係の特殊属性。デメリットを持つ代わりに他属性より
  強力な、玄人向けの枠。
- デッキ構築画面には、各属性列の見出しの下にこのコンセプトが短く表示されます。

## カード

- 種類: **クリーチャー** / **特殊効果** の2種
- 枚数: 6属性(火・水・風・土・天・冥)× 各30種類 = **180種類**
- 特性【唯一】: このマークが付いたカードはデッキに1枚まで。
- カードデータは `data/gamedata.json` に格納。表示用テキストに加えて、
  効果を自動発動させるための構造化データ(`effect: { kind, trigger, params }`)
  を各カードが持っています。

### 実装済みの効果の種類(発動タイミング)

| タイミング | 内容の例 |
|---|---|
| 召喚時/使用時 | 相手クリーチャーにダメージ、HP回復、ドロー、光増加、味方強化、相手弱体化、全体ダメージ など |
| 攻撃時 | 追加ダメージ、対象を問答無用で撃破(代わりに自分のHPが半減) など |
| ターン開始時 | 自身の攻撃力アップ など |
| ターン終了時 | 相手クリーチャーにダメージ、自分にダメージ など |
| 場にいる限り(パッシブ) | 毎ターン光が増える(代わりにドローが減る場合あり)、相手の光を毎ターン削る(代わりに自分もダメージ) など |
| 破壊された時 | HP回復 など |

対象を選ぶ効果(ダメージ・回復・強化など)は、現状は「最も効果的な対象」を
自動選択します(例: ダメージは相手の最もHPが低いクリーチャー、回復は自分の
最も減っているクリーチャー)。手動でのターゲット選択は今後の課題です。

## 対戦相手モード

- **CPU対戦(かんたん)**: 出せる手札をランダムに出し、攻撃も無作為に行う。
- **AI対戦(強め)**: コストの高いカードを優先的に展開し、属性有利や
  とどめが取れる攻撃を優先する。HPが半分を切ると回復の能力を使う。

## デッキ / 場

- デッキ枚数: **ちょうど50枚**(自分はビルダー画面で自由に編集可能。同名カードは
  【唯一】以外いくらでも採用可)
- 場のクリーチャー: 最大5体
- 召喚酔い: 召喚したクリーチャーは**次のターンから**行動可能
- 攻撃: 1ターン1回、**相手クリーチャーを対象**にする
- 直接攻撃: 相手の場にクリーチャーが**1体もいない場合のみ**、プレイヤーへの
  直接攻撃が可能
- **デッキ切れ**: 自分の番でカードを引けなかった場合、その時点で**敗北**

## 光(コスト)

- 毎ターン確定で **5** 配布(能力「豊穣の加護」や一部カードの効果でプラスされる場合あり)
- 光が切れると、光を使うカードは一切使用不可
- 光を増やす手段: 基本は特殊効果カードのみ。【唯一】特性を持つ一部クリーチャー
  だけが例外的に増やせる

## プレイヤー

- HP: 基本 **120**
- 能力: コスト制、合計最大 **13**。ビルダー画面で自由に選択可能(デフォルトの
  ランダム構成を使うこともできる)。全27種類(パッシブ15種/アクティブ12種)。
  - パッシブ(常時効果): やや高コスト。HP増加や光増加などの汎用系に加え、
    6属性それぞれに対応する強化(火・風・水・土・天・冥)が1つずつあり、
    該当属性のカードを使うほど効果を発揮する。
  - アクティブ(発動効果): 1ゲーム1回、光を消費して発動。汎用系6種に加え、
    6属性それぞれのコンセプトに沿った専用アクティブが1つずつある
    (例: 火は追加打点、風は疲労状態の解除、水は全体回復、土は永続強化、
    天は光の急加速、冥は強制除去)。
- 勝敗: プレイヤーのHPが0、またはデッキ切れで決着

## ターンの流れ

1. 光配布(場のカードや能力の影響を反映)
2. 場のパッシブ効果による自分へのダメージなど(あれば)
3. ドロー(手札が5枚未満なら5枚になるまで引く。5枚以上なら1枚だけ引く。引けなければ敗北)
4. ターン開始時効果の発動
5. 行動(カードプレイ・攻撃・アクティブ能力の使用)
6. ターン終了ボタン → ターン終了時効果の発動 → 相手(CPU/AI)のターンが自動で進む

## リポジトリ構成

ファイル名は固定し、ファイルの数を増やさない構成にしています。

```
card-game/
├── README.md
├── index.html          # エントリーポイント(3画面すべてを含む)
├── css/
│   └── style.css       # 見た目
├── js/
│   └── game.js         # ゲームロジック一式(効果エンジン・ビルダー・CPU/AIを含む)
└── data/
    └── gamedata.json    # カード180種+プレイヤー能力のマスターデータ(効果の構造化データ含む)
```

### 更新してもキャッシュが残らないようにする方法

ファイル名は変えず、**URLの末尾のクエリ文字列(`?v=数字`)だけ**を上げます。

- `css/style.css` を更新したら → `index.html` 内の
  `<link rel="stylesheet" href="css/style.css?v=4" />` の数字を上げる。
- `js/game.js` を更新したら → `index.html` 内の
  `<script src="js/game.js?v=7"></script>` の数字を上げる。
- `data/gamedata.json` を更新したら → `js/game.js` 先頭にある
  `const DATA_VERSION = 4;` の数字を上げる(自動的に `?v=数字` で読み込まれる)。

ファイルのリネームは不要で、この3箇所の数字を上げるだけで済みます。

### 更新後にボタンを押しても反応しない・固まったように見える場合

`index.html`自体がブラウザやGitHub PagesのCDNにキャッシュされ、更新前の
古いページが表示され続けていることがあります。

- URLの末尾に `?x=1` のような適当な文字列を足して開き直す(キャッシュを
  確実に回避できます。ダメなら数字を変えて再度試す)
- ブラウザを再読み込みする(タブを閉じて開き直す、プライベートタブで開く)
- 数分待ってから開き直す(GitHub PagesのCDN反映には数分かかることがある)
- GitHub上のリポジトリの `index.html` を直接開き、期待する内容(例:
  `boot-status` という文字列)が含まれているか確認する(反映自体が
  まだできていないケースもあるため)

### デプロイ時の注意(画面が真っ白/CSSが当たらない/ボタンが反応しない場合)

- `css/` `js/` `data/` の**フォルダごと**リポジトリにアップロードされているか
  確認してください。
- ファイルパスは大文字/小文字を区別します。
- 万一 `css/style.css` が読み込めなくても、画面の切り替え自体は
  `index.html` 内のインラインスタイル(セーフティネット)で最低限動作します。
- `data/gamedata.json` の読み込みに失敗した場合は、画面上部に赤い帯で
  エラー内容が表示されます。
